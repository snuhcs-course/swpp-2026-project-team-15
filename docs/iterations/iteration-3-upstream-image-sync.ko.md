# GitHub 변경 확인 및 이미지 응답 호환 — 2026-11-03

사용자 요청: “다른 팀원이 github에 지금 추가로 올린 내용이 있어? 그렇다면 그걸 반영해줘.”

## 확인 및 반영 범위

- 확인 당시 최신 main은 `3c6310e`로 직전 확인과 같았다. 로컬에는 이 아이콘 변경 이력이 아직 없어서 main을 로컬 통합했다. 현재 검토된 냉장고/셰프 아이콘 연결(`ic_launcher`)은 유지했다. 팀원의 `ic_main` 자산을 삭제하거나 덮어쓰지 않았다.
- 새로운 기능은 최아윤 팀원의 `af71dca`(recipe retrieval flow implementation), 브랜치 `feat/iter3-recipe-server`의 당시 HEAD는 `0ce5961`이다. 아직 main에 병합되지 않은 작업이다.
- 이미지 브랜치 전체를 merge하지 않고 Android 이미지 응답 호환 부분을 현재 UI에 맞춰 적용했다. 기본/AI 응답의 `main_image_url`, 상대 URL의 서버 주소 해석, 목록/상세 공통 Coil 이미지 표시를 추가했다.
- 기존 로컬 이미지 리소스·아이콘/정렬/일괄 삭제/기본 재료/테마·우하단 버튼·원본/AI 전환 동작을 유지했다. 원격 이미지가 없거나 로딩에 실패하면 기존 대체 화면을 유지한다.
- 미병합 서버 모델/DB 컬럼/import 변경은 가져오지 않았다. 기존 로컬 DB를 재생성하지 않았고, 서버 배포·GitHub push·PR·휴대폰 설치도 하지 않았다.

## 현재 실제 서버의 한계

공개 OpenAPI의 `RecipeRecommendation`에는 아직 `main_image_url`이 없다. 일반 목록을 조회한20개 결과에도 사진 URL이 없었다. 따라서 이번 코드는 **새 응답을 받을 준비**이며 사진이 이미 실제 서버에서 표시된다는 의미는 아니다. 팀원의 서버 변경·이미지 데이터와 이용 조건을 검토해 별도로 배포해야 실제 사진이 보인다. AI 유료 endpoint는 확인에 사용하지 않았다.

## 검증

이미지 응답 매핑 테스트4개 중 상대/절대 URL 검사2개가 수정 전 실패하는 것을 확인했다. 이후 전체 JVM **92개 통과**(실패/오류/스킵0), Cloud Test 빌드 성공, 린트 오류0/경고36/hint1을 확인했다. 새 기본/AI 응답의 이미지 URL 보존도 검사했다. 로그는 `.superpowers/remote-image-compat-green.log`에 있다. 현재 런처 연결을 유지하면서 팀원 아이콘 자산도 보관하므로 미사용 리소스 경고가 포함된다. 이번에는 원격 이미지 실기기 표시나 다운로드 성공을 주장하지 않는다.

이 변경은 팀원의 Android 이미지 기능을 현재 로컬 코드에 맞춰 AI가 적용한 것이다. 기존 이미지 리소스 필드를 제거하지 않고 새 URL 필드를 추가했으며, 사용자의 수동 코드 수정으로 기록하지 않는다. 휴대폰에 설치된 직전 버전과 기존 APK 공유 파일은 변경하지 않았다.
