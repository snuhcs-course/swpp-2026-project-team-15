# 연구와 구현: 2026-09-27 ~ 2026-10-06

근거: 팀 대화 요약, 브랜치 커밋, Recipe Database Wiki, PM이 확인한 날짜. 독립된 결과를 통합 서비스로 표현하지 않는다.

| 날짜 | 논의와 근거 |
| --- | --- |
| 9월 27~30일 | 레시피 데이터와 이미지 인식 방식을 조사했다. 연구 브랜치에는 뒤이어 여러 파이프라인 후보와 벤치마크가 추가됐다. 입력은 모의 재료 문자열이며 실제 사진 정확도는 아니다. |
| 10월 4일 | 레시피 DB 구조를 논의했다. SQLite로 로컬 스키마·입력 실험을 먼저 하기로 했고 운영 DB·ORM은 미정이다. |
| 10월 5일 | Android 진행 상황과 DB 스키마·입력 스크립트·설정 문서를 공유했다. |
| 10월 6일 | Android 시제품과 레시피 데이터를 공유하고 서버의 역할을 논의했다. 앱은 목업 데이터를 사용하며 서버에 연결되지 않았다. |

원본 데이터에는 기본정보·조리 과정·주재료/부재료/양념 구분과 요리 전체의 재료량이 있다. 로컬 DB에는 레시피 537개, 단계 2,870개, 고유 재료 701개, 레시피-재료 관계 5,933개가 있다. 조리도구·알레르겐 관계는 비어 있다. 제공기관은 대표·단계 이미지 URL을 사용하지 않는다고 답했다. 1인분 변환, 레시피 선정, 명칭 정리, 조리도구·알레르겐 연결이 남아 있다.

후속 작업은 두 서버 API 계약, 재고 저장 위치, 실제 사진 평가다. 관련 자료: [Recipe Database Wiki](https://github.com/snuhcs-course/swpp-2026-project-team-15/wiki/Recipe-Database), [Iteration 1 현황](../iterations/iteration-1-status.ko.md).
